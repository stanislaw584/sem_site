# Roadmap

## Этап 0. Документация и модель контента

Цель: согласовать направление до написания кода.

Задачи:

- согласовать разделы MVP;
- согласовать шаблон статьи;
- согласовать стек;
- решить, какие языки входят в первую версию;
- определить официальные контакты и ссылки, которые нужно проверить перед публикацией.

Результат:

- продуктовая концепция;
- информационная архитектура;
- технический подход;
- первичный backlog контента.

## Этап 1. Статический MVP

Цель: сделать первую рабочую версию сайта без бэкенда.

Задачи:

- создать проект на Vite + React + TypeScript;
- сверстать главную страницу по референсу;
- добавить карточки основных разделов;
- добавить страницы статей;
- добавить маршруты языков;
- добавить футер с быстрыми ссылками и контактами;
- добавить первичный контент;
- довести мобильную версию.

Первый набор статей:

- Активировать личный кабинет ДВФУ.
- Войти в корпоративную почту.
- Найти расписание.
- Понять учебный план.
- Проверить оценки.
- Исправить ошибку в оценке.
- Узнать про пересдачи.
- К кому обратиться по учебе.
- К кому обратиться по визе и регистрации.
- К кому обратиться по общежитию.
- Проблема с личным кабинетом или почтой.
- Нужна психологическая помощь.

Критерии готовности:

- студент может перейти с главной страницы к каждой статье;
- сайт нормально работает на desktop и mobile;
- контент отделен от UI-кода;
- проект успешно собирается.

## Этап 2. Расширение контента

Цель: покрыть основные темы хэндбука простым языком.

Задачи:

- переписать разделы хэндбука в формат коротких практических статей;
- добавить связанные статьи;
- добавить блоки контактов;
- добавить скриншоты и схемы там, где они нужны;
- добавить английские версии;
- добавить китайские версии для самых важных страниц.

Приоритетные темы:

- сессия и пересдачи;
- академический отпуск и отчисление;
- стипендии;
- библиотека;
- наука и конкурсы;
- тревел-гранты и академическая мобильность;
- работа и ярмарки вакансий;
- обратная связь.

## Этап 3. Поиск и обратная связь

Цель: упростить поиск информации.

Задачи:

- добавить Pagefind;
- сделать страницу результатов поиска;
- добавить ключевые слова и синонимы на русском, английском и китайском;
- добавить кнопку "Была ли страница полезной?";
- добавить ссылку "Сообщить о проблеме".

На этом этапе бэкенд все еще не обязателен. Обратную связь можно отправлять в Google Form или университетскую форму.

## Этап 4. Редактирование без разработчика

Цель: дать менеджеру или редактору возможность менять текст.

Рекомендуемый вариант:

- подключить Decap CMS или TinaCMS;
- оставить Git источником правды;
- настроить процесс: черновик, проверка, публикация;
- добавить поля: ответственный, дата проверки, источник информации.

Альтернатива:

- временно использовать Notion или Google Sheets как источник контента, если редакторам так удобнее.

## Этап 5. Поддержка актуальности

Цель: сделать информацию надежной и актуальной.

Задачи:

- назначить владельцев контента по разделам;
- добавить график проверки важных страниц;
- показывать дату последнего обновления;
- сделать чеклист перед публикацией изменений;
- подключить аналитику популярных страниц и неудачных поисковых запросов.

## Первый спринт

Оценка: 5-7 рабочих дней.

Задачи:

1. Создать проект.
2. Сделать главную страницу и layout.
3. Сделать шаблон статьи.
4. Добавить 8-12 приоритетных статей на русском.
5. Добавить английские версии этих страниц.
6. Проверить мобильную версию.
7. Развернуть preview-ссылку.
